# Internationalization (i18n)

Lilo ships English, French, Spanish, Simplified Chinese (`zh-Hans`), Brazilian Portuguese (`pt-BR`), Russian, Ukrainian (`uk`) and German (`de`). There are two small, dependency-free translation layers:

| Layer | Drives | Source of truth | Follows |
|-------|--------|-----------------|---------|
| **Web chrome** (Svelte UI) | tabs, sidebar, command bar, settings, panels | `lilo-ui/src/lib/i18n/locales/*.json` | the in-app **Language** selector (Settings > General), instantly |
| **Native** (AppKit) | menu bar, native dialogs | `lilo-ui/src/lib/i18n/locales/*.json` (`native` namespace) | the same in-app choice, else the macOS system language - applied on next launch |

Both layers translate from the same JSON catalogs - there is no second place to maintain.

One selector drives everything: the web chrome switches instantly; native menus/dialogs pick up the choice on the next launch (the menu bar is built once at startup). When no choice has been made, native falls back to the system language.

## Web UI

Call `t()` with a dotted `namespace.key`:

```svelte
<script lang="ts">
  import { t } from "../lib/i18n/state.svelte";
</script>

<button aria-label={t("findBar.closeFindBar")}>×</button>
<span>{t("downloadIndicator.downloadsCount", { count })}</span>
```

- `t(key, params?)` resolves the active locale, falls back to English, then to the key itself (so a missing string is visible, never blank).
- Placeholders are `{name}` style, filled from `params`.
- A numeric `count` is digit-grouped for the locale, and picks a plural form when the key holds one per [plural category](https://cldr.unicode.org/index/cldr-spec/plural-rules) instead of a string: `"pagesImported": { "one": "{count} page imported.", "other": "{count} pages imported." }`. A category the catalog lacks (French `many`) falls back to `other`.
- `t()` reads a reactive rune, so changing the language updates every label instantly - no reload.

**Architecture** (`lilo-ui/src/lib/i18n/`):

- `translate.ts` - pure resolver; English is imported up front, other catalogs load on demand (`loadCatalog`). Unit-tested (`translate.test.ts`).
- `state.svelte.ts` - the reactive current-locale rune + `t()`. (Runes live here so plain `.ts` files, and the unit tests that run them under `tsx`, never import them.)
- `locales/*.json` - message catalogs, namespaced by feature.

The default locale comes from `navigator.language`; the Settings selector persists an override via the `locale` setting and applies it on load.

### Add or change a string

1. Add the key under the right namespace in **every catalog** (`en.json`, `fr.json`, `es.json`, `zh-Hans.json`, `pt-BR.json`, `ru.json`, `uk.json`, `de.json`).
2. Use `t("namespace.key")` in the component.

`translate.test.ts` fails `make ui-test` (and CI) if any catalog is missing a message or changes its placeholders. Plural categories vary by locale: Russian defines `one`, `few`, `many` and `other` (fractions).

> A pure `.ts` model that needs translation should expose catalog **keys** (e.g. `labelKey`) and let the Svelte consumer call `t(key)` - see `settingsPanelModel.ts`. This keeps the model importable by the `tsx` unit tests, which can't load Svelte runes.

### Add a language

1. Add `locales/<code>.json` with the same keys as `en.json`.
2. Register it in `translate.ts`: extend the `Locale` type, `SUPPORTED_LOCALES`, `loadCatalog`, and `resolveLocale` for regional catalog codes.
3. The key and placeholder parity tests in `translate.test.ts` cover every supported locale. Add resolution and count-formatting cases for the new locale.
4. The native generator discovers every catalog automatically. Teach `Lilo/App/Localization.swift` any script or region mapping it needs, then add tests in `LiloTests/App/LocalizationTests.swift`.
5. Add system prompts and Shortcuts strings under `Lilo/Resources/<code>.lproj`, register the locale in `Lilo/Info.plist` and `project.yml`, and run `make project-sync`.
6. Add emoji annotations in `scripts/generate_emoji_data.py` and the lazy loader in `emojiPickerModel.ts`; run `make emoji-data` and cover search in `emojiPickerModel.test.ts`.
7. Add `docs/readme/README_<code>.md` and link it in the language selector of every README, including the root English version (see [README translations](#readme-translations)).

Simplified Chinese resolves from `zh`, `zh-CN`, `zh-SG` and explicit `zh-Hans` tags. An explicit script takes precedence over the region; Traditional Chinese tags (`zh-Hant`, `zh-TW`, `zh-HK`, `zh-MO`) use the English fallback.

Portuguese system tags, including `pt` and `pt-BR`, use the Brazilian Portuguese catalog. The in-app choice is stored as `pt-BR`; CLDR's `pt` annotations supply its emoji names.

## README translations

The root [README.md](../README.md) is the English source. Full translations for the supported
app languages live in `docs/readme/README_<code>.md`, using the same locale codes as the catalogs.
Each README starts with a language selector: the current language is bold, and the others link
to their versions using their native names.

When the English README changes, update the matching sections in every translation. Keep commands,
requirements and feature coverage in sync. Translate headings, prose and image descriptions;
adjust relative links and image paths for `docs/readme/`, and use anchors that match the translated
headings.

## Native (AppKit)

The English string is the key:

```swift
menu.addItem(withTitle: "New Tab".localized, action: ...)
```

`String.localized` returns the translation for the active native locale - the in-app language choice (persisted to `UserDefaults` when the selector changes), or the system language as a fallback - and the original English otherwise. Strings absent from the table stay English, so wrapping a string is always safe. Interpolated strings use `String(format: "Install %@?".localized, name)`.

The translations live in the **`native` namespace of the shared catalogs** (`locales/*.json`), keyed by the English string. `make ui-build` runs `scripts/generate_native_strings.py`, which compiles that namespace into `Lilo/Generated/NativeStrings.swift` (generated, gitignored - same pattern as the embedded UI bundle).

To translate a native string: wrap it in `.localized`, add an `"English": "Français"` row under `native` in `en.json` (identity) and each other catalog (translation), then `make ui-build`.

`nativeStrings.test.ts` (run by `make ui-test`) scans `Lilo/` for literals that reach `.localized`, directly, through a ternary or through a localizing helper, and lists any without a row in every catalog. Localize a literal where it is written, not after it went through a dictionary or a variable, so the scan sees it.
